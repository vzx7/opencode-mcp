# ADR-004: Локализованные JSON-промты и LLM-only scoring

**Статус:** принято  
**Дата:** 2025-04

## Контекст

Система должна возвращать аудит на трёх языках (ru, en, zh). LLM получает промт и выставляет score.
Первоначально движок также корректировал score детерминированными штрафами.

Нужно решить: где хранить тексты промтов, и кто отвечает за финальный score.

## Решение

### Хранение промтов

Все тексты промтов вынесены в JSON-файлы: `internal/llm/prompts/{en,ru,zh}.json`.

Каждый файл содержит:
- `system_role` — роль для LLM
- `labels` — все строковые метки разделов
- `review_focus` — список фокус-пунктов
- `json_schema_instruction` + `json_schema` — инструкция по формату ответа
- `compliance` — блок для compliance check
- `module_audit` — блок для module audit

Файлы загружаются один раз при старте (`init()` в `loader.go`) и кешируются в памяти.

### LLM-only scoring

Score в `AuditReport` устанавливается **исключительно LLM**. Движок (engine + executor)
не применяет никаких числовых штрафов к score.

Движок добавляет только issues (без влияния на score):
- Import cycle → severity CRITICAL
- Layer violation → severity HIGH

## Обоснование

**Локализация в JSON:**
- Изменение текста промта не требует перекомпиляции
- Переводчик редактирует JSON без знания Go
- Поддержка нового языка = добавить один файл
- Промт остаётся на одном языке от начала до конца — LLM не переключает язык внутри ответа

**LLM-only scoring:**
- Детерминированные штрафы (score -= 20 за цикл) создавали непредсказуемый итог:
  LLM выставляет 85, движок снимает 40 → 45 без архитектурного обоснования
- LLM имеет больше контекста для оценки severity: видит код, граф, метрики одновременно
- Движок не может оценить архитектурный impact так же хорошо, как LLM с полным промтом
- Cycles и violations передаются LLM в промте — LLM уже учитывает их в score

## Рассмотренные альтернативы

**Промты в Go-коде (строки):** рефакторинг требует перекомпиляции, нет разделения контента и логики.  
**Промты в отдельном сервисе:** избыточная инфраструктура для простой задачи.  
**Комбинированный scoring (LLM + движок):** непредсказуемый результат, двойное ответственность.  
**Движок как единственный источник score:** невозможно учесть качественные архитектурные паттерны.

## Последствия

- Промты загружаются из файловой системы — путь определяется при старте через `findPromptsPath()`
- Если JSON-файл не найден — предупреждение в лог, инструмент продолжает работу с пустым промтом
- Изменение рубрики оценки или фокус-листа: только правка JSON, без правки Go-кода
- Score из LLM может быть 0–100; если LLM не вернул валидный JSON — fallback score = 75
