# System Context

## Акторы

| Актор | Описание |
|---|---|
| **AI-ассистент** | Claude Desktop, OpenCode, Cursor — основной клиент. Вызывает инструменты через MCP и интерпретирует ответы для пользователя. |
| **Разработчик** | Пользователь, который через AI-ассистента запрашивает аудит. Не взаимодействует с сервером напрямую. |
| **CI/CD-пайплайн** | Опциональный клиент: вызывает `architecture_compliance_check` как gate в процессе сборки через HTTP. |

## Внешние системы

| Система | Связь | Протокол |
|---|---|---|
| **OpenAI API** | Исходящий. LLM-запросы для анализа кода. | HTTPS, JSON |
| **Anthropic API** | Исходящий. Альтернативный LLM-провайдер. | HTTPS, JSON |
| **Git** | Локальный процесс. `git log` для сбора hotspot-данных. | subprocess |
| **Файловая система** | Локальный доступ. Чтение исходников, запись отчётов. | OS API |

## Границы системы

**Внутри границы:**
- Приём и маршрутизация MCP-запросов
- Авто-определение языка программирования анализируемого проекта
- Статический анализ проектов: граф зависимостей, метрики файлов, code snapshot
- Формирование промтов и вызов LLM
- Формирование и сохранение отчётов

**Вне границы:**
- Интерпретация отчётов и принятие решений — задача AI-ассистента и разработчика
- Исправление выявленных проблем — задача разработчика
- Обучение LLM-моделей — внешние провайдеры
- Управление версиями анализируемого проекта

## Предположения

- Анализируемый проект находится на локальной файловой системе, доступной серверу
- Для LLM-анализа требуется интернет-соединение (кроме режима mock)
- Язык программирования проекта определяется автоматически по маркерным файлам; явное указание через `programming_language` перекрывает авто-определение
- Для Go-проектов: граф импортов строится через `go/ast` без запуска компилятора и без установки зависимостей
- Для Python и TypeScript: статический анализ (граф импортов) пока не реализован; LLM получает исходный код и работает без графа
- Git опционален: если репозитория нет, hotspot-анализ пропускается без ошибки
