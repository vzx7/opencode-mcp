# ADR-002: Абстракция LLM-провайдеров через интерфейс

**Статус:** принято  
**Дата:** 2025-04

## Контекст

Система должна поддерживать как минимум два реальных LLM-провайдера (OpenAI, Anthropic)
и mock-режим для тестирования. API у провайдеров разные (структура запроса, заголовки аутентификации,
формат ответа).

## Решение

Ввести единственный интерфейс `LLMProvider`:

```go
type LLMProvider interface {
    Complete(ctx context.Context, prompt string, language string) (string, error)
    Name() string
}
```

Каждый провайдер реализует интерфейс независимо. Вызывающий код (`ToolExecutor`) работает только
с интерфейсом.

## Обоснование

- Единственное место, где нужна абстракция: реальных реализаций несколько, и они взаимозаменяемы
- Mock-провайдер делает тесты полностью детерминированными и быстрыми без сети
- Интерфейс минимален (2 метода) — нет риска interface bloat
- Новый провайдер (Google, local Ollama) добавляется без изменения ToolExecutor

## Принцип: абстракция только там, где нужна

Все остальные компоненты используют конкретные типы напрямую. Нет смысла вводить
`AnalyzerInterface` или `ReportPersisterInterface` — у них нет альтернативных реализаций.

## Рассмотренные альтернативы

**Без интерфейса (switch по имени провайдера):** тесты требуют реального HTTP, добавление провайдера
требует правок в вызывающем коде.  
**Несколько интерфейсов:** избыточно при одном реальном паттерне использования.

## Последствия

- `ToolExecutor` получает `LLMProvider` через конструктор (DI)
- Mock подставляется в тестах без изменения `ToolExecutor`
- Провайдер конфигурируется при старте сервера, не при каждом вызове инструмента
- Переопределение провайдера per-call возможно через аргументы инструмента
