Ты — senior Go engineer и system architect с опытом построения AI-инструментов, MCP серверов и систем архитектурного анализа кода.

Твоя задача — спроектировать и реализовать MCP server на Go, который будет использоваться как AI Tech Lead для аудита и ревью кода.

---

# 🎯 ЦЕЛЬ СИСТЕМЫ

Сервер должен предоставлять MCP tools для анализа кода и архитектуры проекта.

Он НЕ является LLM.
Он является orchestration layer, который:
- получает контекст проекта
- формирует структурированное представление системы
- вызывает LLM (через абстрактный provider interface)
- возвращает структурированный аудит

---

# 🧠 ОСНОВНЫЕ ЗАДАЧИ MCP СЕРВЕРА

## 1. Архитектурное ревью проекта (Tech Lead Review)

Tool:
- name: `architecture_review`

Функция:
- анализирует проект как систему целиком
- выявляет архитектурные проблемы
- оценивает качество слоёв и границ
- оценивает масштабируемость и maintainability
- возвращает structured report

---

## 2. Ревью всего репозитория на соответствие заданной архитектуре

Tool:
- name: `architecture_compliance_check`

Функция:
- принимает описание целевой архитектуры (rules / constraints)
- анализирует текущую структуру репозитория
- находит нарушения архитектурных правил
- возвращает список нарушений + severity + рекомендации

---

## 3. Аудит отдельного файла / модуля

Tool:
- name: `module_audit`

Функция:
- принимает путь к файлу (или модулю)
- извлекает контекст (зависимости, вызовы, usage)
- делает локальный аудит:
  - correctness
  - design quality
  - coupling / cohesion
  - potential bugs
- возвращает structured report

---

# 🧱 ТРЕБОВАНИЯ К АРХИТЕКТУРЕ MCP СЕРВЕРА

## 1. Go stack

Использовать:
- чистый Go (без лишних фреймворков)
- стандартные библиотеки где возможно
- структурированный код

---

## 2. Архитектурное разделение

Обязательно разделить на слои:

- /cmd (entrypoint)
- /internal/mcp (MCP server core)
- /internal/tools (MCP tools implementation)
- /internal/analyzer (code & repo analysis engine)
- /internal/llm (provider abstraction layer)
- /internal/domain (data models: audit reports, findings, severity)

---

## 3. LLM abstraction layer

Создать интерфейс:

type LLMProvider interface {
    Complete(prompt string) (string, error)
}

Реализовать так, чтобы можно было подключить:
- local models
- cloud models
- external APIs

НО оставить реализацию абстрактной (mock допустим)

---

## 4. Repo analysis engine

Сервер должен уметь:

- сканировать файловую структуру
- строить project map:
  - modules
  - entrypoints
  - dependencies
- определять архитектурные слои
- находить потенциальные нарушения границ

---

## 5. Output format (очень важно)

Все ответы MCP tools должны быть строго структурированы:

type AuditReport struct {
    Score int
    Summary string
    Issues []Issue
    Recommendations []string
}

type Issue struct {
    Severity string // critical | high | medium | low
    Message string
    Location string
    Suggestion string
}

# 🧠 ЛОГИКА РАБОТЫ СИСТЕМЫ

## architecture_review

1. Build project map
2. Identify architecture style
3. Analyze coupling / cohesion
4. Evaluate maintainability
5. Return score + report

---

## architecture_compliance_check

1. Parse architecture rules
2. Compare rules with project structure
3. Detect violations
4. Rank severity
5. Return structured diff-like report

---

## module_audit

1. Load file/module
2. Extract dependencies
3. Analyze logic
4. Detect issues:
   - complexity
   - design smell
   - coupling
5. Return report

---

# ⚠️ ВАЖНЫЕ ОГРАНИЧЕНИЯ

- MCP сервер НЕ должен зависеть от конкретной LLM
- вся LLM логика через abstraction layer
- система должна быть расширяемой
- код должен быть production-grade, не PoC
